# CellFlow V0.2 hardening

V0.2 focuses on correctness under duplicate/retried serverless execution rather than adding unrelated protocol integrations.

## Correctness changes

- CCC signs once with `signTransaction()`; the deterministic CKB tx hash is persisted before broadcast.
- Broadcast RPC errors and post-broadcast CellFlow bookkeeping errors are different error classes.
- Execution updates use optimistic concurrency and retry instead of silently accepting a stale write.
- Intent creation, execution transition, audit event and webhook outbox creation share database transactions.
- Reconciliation workers and webhook workers claim rows with expiring leases and `FOR UPDATE SKIP LOCKED`.
- Vercel Workflow starts are deduplicated per execution, with stale-run recovery.
- Unchanged chain observations update the execution snapshot without generating duplicate state events/webhooks.
- Reconciliation remains active while expected Cell assertions are `PENDING` even if the chain confirmation policy is satisfied.

## CKB-specific changes

- A reconciliation observation uses one RPC endpoint from start to finish instead of mixing responses from different nodes.
- Previously committed blocks are checked with `get_block_hash` before a downgrade is called a reorg.
- A lagging `pending`/`proposed` response cannot erase a prior canonical commit by itself.
- Expected Cell assertions support `mode: created` and `mode: live`.
- `live` mode verifies the output via CKB `get_live_cell` after checking the committed transaction output.
- Empty assertions are rejected and capacity is compared as an integer rather than as textual hex.

## Security/operations changes

- `CELLFLOW_ENCRYPTION_KEY` is server-only and no longer used to bootstrap projects.
- `/api/setup` uses a separate `CELLFLOW_BOOTSTRAP_TOKEN` and can be disabled in production.
- Browser API keys are kept in page memory instead of `sessionStorage`/`localStorage`.
- Project-wide database-backed API rate limiting is enabled.
- RPC URLs receive the same public-address/HTTPS SSRF checks used for webhook destinations.
- Webhook delivery rows use claim leases and expired claims can be recovered after worker crashes.
- Webhook test delivery is project-scoped rather than invoking another tenant's due queue.
- Evidence exports are persisted and deduplicated by evidence SHA-256.
- Migrations are versioned through `schema_migrations`.
- Database constraints protect lifecycle enum values and non-negative counters.

## Validation available without network dependencies

`npm test` currently covers lifecycle/reorg behavior, Cell assertion semantics, repository hardening invariants and repository-tree completeness. A full dependency install, production build and Postgres-backed CI run are defined in `.github/workflows/ci.yml` for a network-enabled environment.

## Deliberately outside V0.2

Fiber orchestration, RGB++, AI agents, custody, billing and multi-chain abstractions remain out of scope. The product boundary remains durable CKB business-intent execution and state-transition recovery.
