# CellFlow V0.3 production/funding upgrade

This release layers production controls and reviewer-verifiable evidence on top of the existing durable CKB transaction recovery model.

## Product/operations features

- project-wide metrics rather than dashboard-page-derived counts;
- operational health API/dashboard for reconciliation backlog, stale intents, webhook failures and API-key expiry;
- durable operator notes in the intent timeline;
- signed-webhook disable, health counters and failed-delivery replay;
- read-only project evidence export plus admin-only durable evidence recording;
- release version/commit identity in project evidence;
- updated API key/webhook management UX.

## Reliability

- multiple CKB RPC fallbacks;
- bounded RPC timeouts and response sizes;
- per-process RPC circuit-breaker cooldown;
- readiness validation for database, RPC, CKB network identity, optional pinned genesis, secret configuration, setup lock, HTTPS transport and fallback topology;
- maintenance task failure isolation;
- bounded JSON request bodies;
- database indexes for operational-health paths.

## Security

- scoped API keys (`read`, `write`, `admin`);
- optional API-key expiry and expiry-aware authentication/revocation;
- rate-limit buckets per API-key identity;
- request correlation IDs and structured error logs;
- production security headers and no-store/no-index API headers;
- detailed readiness posture redacted from unauthenticated production callers;
- explicit admin permission for durable project-evidence mutation.

## Funding/reviewer readiness

- machine-readable project evidence with SHA-256 fingerprint;
- reviewer verification guide;
- production operations runbook;
- security policy/model;
- OpenAPI 0.3 contract;
- release preflight command that makes missing reproducibility artifacts explicit;
- milestone/evidence strategy designed around verifiable outputs rather than broad claims.

## Release evidence

- `RELEASE_STATUS.json` captures the static preflight result for this export.
- `npm run release:report` regenerates that report; `npm run release:check` fails closed on blockers.

## Validation

- `npm run verify`: **65/65 deterministic tests pass**, then critical implementation-tree verification passes.
- Touched TypeScript backend files pass Node strip-types syntax checks.
- OpenAPI YAML parses successfully.

## Explicit release blocker in this exported environment

The source input does not contain `package-lock.json`, and this execution environment cannot resolve `registry.npmjs.org`. Therefore a truthful production release still requires generation/commit of the lockfile and a clean network-enabled `npm ci`, full workspace typecheck, and Next.js production build. `npm run release:check` intentionally reports the missing lockfile as a blocker until that is done.
